Media Plan & Budget

One page in the portal (Annual Media Plan, step mediaplan) where a client sets up each year's marketing budget and turns it into a channel-by-channel, month-by-month plan. Two ways in share one front door: upload the budget file the client already has (auto-recognized, category-mapped, confirmed), or build it by hand from a total — or gross revenue × a target % — through stage weighting, a recommended channel mix, and a monthly curve. A confirmed budget then drives Active Channels, the Plan Pacing / Budget Tracking / Channel Mix reports, and Campaign Creation's channel picker. This document is the current-state reference, verified against the live code on 2026-09-05.

Seven rounds of direct client review on 2026-09-05 turned a confusing, duplicated page into one sequenced flow. What changed structurally, checked against the code:

Confirmed solid

mbuApplyPageMode() is the single place that decides what's on screen, from two inputs: does a budget exist for the selected year+scope, and which Setup path was picked. No budget → only Plan Setup shows. See §01.

Confirmed solid

Rounds 5–6 had built a duplicate manual path (a synthetic upload with a pre-filled grid and its own revenue calculator). Round 7 deleted it; "Manually add" now is the Media Plan wizard, sequenced as Steps 1–4. See §03.

Confirmed solid

One Budget detail view, whichever way the budget was made

mbdRenderUnified() renders the same four components — Marketing Loop allocations, channel totals, sub-channels rolling up to them, monthly distribution — from an uploaded budget or a saved Media Plan, with non-working spend beside working and a read-only total marketing spend. See §07.

Confirmed solid

Active Channels are the one allocation gate

computeRecommendedMix() filters by state.activeChannels only; a confirmed upload rewrites that set to its mapped channels and the UI adopts it immediately. See §08.

Plan Setup — the front door§ 01

The first card on the page (#mbuPlanSetupCard): one Budget scope toggle (Domestic / International), one Budget year chip row (the only year control on the page — it also switches which year's Media Plan is loaded, via setMbuYear() → setMpYear()), and a status block rendered by mbuRenderPlanSetup().

"Budget exists" (mbuBudgetExists()) means a confirmed Marketing Budget Upload for the selected year+scope (mbuHasActiveBudget()) or, for Domestic only, a saved Media Plan for that year (mpHasSavedPlan() — requires a backend id, so an in-progress unsaved draft is still "Setup"). media_plans rows have no scope, which is why a saved plan only counts toward Domestic.

Upload path§ 02

Accepts .csv or .xlsx in whatever layout the client already has — a flat table or a multi-block export that repeats a header per section. The year and scope come from Plan Setup; a second confirmed budget for the same year+scope is refused (HTTP 409).

01

Upload & analyze

The file is stored (uploaded_files), the grid is scanned for month-name header rows (one = flat table; several = multi-block), and category / Working–Non-Working / month / total columns are guessed. Rows whose total equals the sum of their block are flagged as subtotals so they aren't double-counted.

POST /api/accounts/:id/marketing-budget-uploads
02

Import with the best-guess mapping

Runs automatically (mbuConfirmImport()) — the old per-column "confirm each column" panel was removed in Round 4; Step 2 below is the review screen. Line items are written per raw category × month, with the Working/Non-Working status token normalized (WORKING MEDIA, NON-WORKING MEDIA, etc.).

POST /api/accounts/:id/marketing-budget-uploads/:uploadId/confirm
03

Mapping evaluation

Laid out like a financial statement in three columns — A the category (bold), B the amount, C the mapping/label, with one "Please update as needed" header per section. Working media first: each raw category with Verilume's suggested category as an always-editable grouped dropdown in column C (Total Channel → subcategory, §06; an "International" line can map to International — total only). This is where the client assigns sub-channel allocations: a category mapped to a group's "Total/Unspecified" bucket offers "Split into … sub-channels →", which adds that group's sub-channels as editable $ rows; whatever is assigned to them comes out of the bucket (the group header shows the remainder), so sub-channels feed the total and nothing is counted twice. Non-working spend follows underneath in the same columns, no mapping required, with column C an editable name (saved as a display label) and "+ Add category" for lines the file didn't have (saved as line items via POST …/nonworking-lines). Every total sits under column B; a read-only Total marketing spend (working + non-working) closes the screen.

GET …/category-mapping · POST …/category-overrides · POST …/category-labels
04

Submit as final

Only Working categories must be mapped. On confirm the upload becomes confirmed, the account's Active Channels are recomputed from the mapped categories (Domestic only — §08), and the page hands off to the Media Plan with the Annual Marketing Budget pre-filled from the upload's Working total.

POST …/confirm-categories
05

Export

The confirmed view's default export is a monthly-detail CSV: one row per Verilume category, Jan–Dec + Total. CSV rather than .xlsx because the Excel generator (xlsx_gen.py) is a Python subprocess that doesn't run on Vercel's Node runtime.

GET …/export.csv

A sample template with the recognized layout is downloadable from the upload card (GET /api/marketing-budget-upload-template.csv, unauthenticated).

Manual path — the Media Plan wizard§ 03

Four steps inside #mpPlanSection. Step 2 appears once a Working Marketing Budget exists; Steps 3–4 once a channel mix has been built (mpRenderPlanSteps()). Domestic only.

The upload feeds the manual process (R8)

Per direct instruction, the two paths are one process: the upload is a head start on Steps 1–4, not a separate end state. Confirming an upload (or "Build the media plan from this budget" on the Budget detail) runs mpSeedPlanFromUpload(): Step 1 gets the working total and non-working lines; Step 2 gets the Marketing Loop split — the five stage percentages and dollar totals — derived from the uploaded channel mix (or the client's assigned stage dollars), saved as the account's split so the table, the pie and the channel build agree; Step 3 gets channel rows built from the uploaded categories (the Active-Channels crosswalk plus a plan-seeding crosswalk for the additive subcategories, MBD_SEED_CROSSWALK; categories with no media channel — e.g. International total-only — are named on screen and left off the rows); Step 4 gets the monthly curve from the uploaded months. The page opens on Step 2 so the Loop percentages and totals are the first thing seen, and the client reviews, edits and saves exactly as in the manual path. Once the plan exists, the Budget detail shows the refined plan with the upload named as its source; "Re-seed the plan from this budget" starts over from the upload.

1

Budget

Working Marketing Budget — Type an amount, or Calculate from revenue: gross revenue × a target % of working marketing spend (dropdown, 3%–25% in whole steps, default 7%), with an explicit apply. Beside it, read like a financial statement: Non-working Budget (read-only, the sum of the Non-Working Media lines, with a link to add/edit them), Sales Budget (optional), and Total Sales and Marketing (read-only, working + non-working + sales). The chosen % is remembered on the plan (marketingBudgetPct) but is not a live formula. The revenue field reads the same for every industry — the former Travel/Cruise "Purchase Year" copy and recognition schedule were removed as hard-coded client content (R8).

2

Stage Weighting — one full-width card, the Marketing Loop pie inside it

One row per Media Loop stage (Awareness, Consideration, Purchase, Loyalty, Advocacy) showing the default split for reference plus an editable Share % and an editable Budget $ (share × Step 1). Editing either rebalances the other four proportionally so the split always totals 100%, and saves immediately as the account's override (accounts.stageBudgetWeightsOverrideJson). The pie, this table and the channel allocation all read the same numbers (getIndustryStageWeights(); a saved override is used exactly, with no industry nudge). A suggested split from the Business & Revenue Profile survey can be applied in one click when available. The card states what the weights are based on (mpWeightingBasisText()): the account's saved split or the industry/default stage split, industry-specific channel weights where a table exists (Automotive Sales & Service, Financial Services / Banking today) or the cross-industry table otherwise, and — new in R8 — an adjustment for the audience's generation and wealth tier from Company Profile (GENERATION_CHANNEL_AFFINITY / WEALTH_CHANNEL_AFFINITY, directional media-consumption multipliers averaged across the selected segments and renormalized within each stage; editorial heuristics, disclosed as such). "Continue → build channel mix" is at the bottom of this card.

GET / POST /api/accounts/:id/stage-weights
3

Channel mix — review & adjust

A card like the other steps (R8), with the Full Year / quarter / month View budget selector at the top of the funnel-stage sections it filters. applyRecommendedMix() splits each stage's dollars across its channels by effectiveStageChannelWeights() (industry-specific where one exists, audience-adjusted), blended toward the account's own prior-year channel shares when history exists, limited to Active Channels (§08), and dropping channels that would fall under their minimum-viable spend (listed as "Not recommended this pass"). Every row's Annual $ and Est. CPM are editable; an inline "Add a channel" card adds any stage+channel. The per-channel "playbook" block (audience / creative / KPI notes) is no longer rendered here — it read as campaign-level content (R8).

4

Monthly distribution, then Save plan

One curve for every channel: Flat (even), Revenue curve (the account's AOV seasonality, editable per month) or Custom %. Stored as monthlyMode flat | curve | manual plus the month table. Save plan writes the plan, its allocations and periods; saving is what flips Plan Setup to Active.

POST /api/accounts/:id/media-plan

Leverage previous year§ 04

One picker with two kinds of source, so there is a single carry-forward affordance rather than two:

  • A prior confirmed upload (any year/scope) — copied server-side into a new upload for the target year+scope as a draft (pending_category_mapping), never auto-confirmed: last year's numbers are very likely stale, and a silent copy shouldn't rewrite Active Channels without a human looking. It opens on the same mapping-review screen as a real upload. POST …/marketing-budget-uploads/carry-forward
  • A prior saved Media Plan (Domestic) — copied client-side by mpCarryForwardFromYear() into an unsaved draft (fresh allocation ids, months recomputed, Non-Working vendors deliberately not copied) that opens in the Manual steps for review and Save.

International scope & total-only§ 05

International is a different office with the same media-mix opportunity, so budgets are keyed on (accountId, year, scope) — a Domestic and an International budget for the same year coexist, each with its own upload/mapping flow and its own Active/Setup status. Pre-existing rows read as Domestic via COALESCE(scope,'domestic').

For an organization that doesn't want a full International plan, Plan Setup offers "Just track a total budget (skip channel detail)": one number, stored as an auto-confirmed upload flagged totalOnly with a single line item mapped to Other/Uncategorized. Its Active state shows the figure with an "Edit total" action instead of a channel-level detail screen. The channel-level Media Plan builder (Manual path) is Domestic-only for now.

⚠ International does not drive Active Channels

recomputeAccountActiveChannels() runs for Domestic confirms only. Because it replaces the account's channel set wholesale, letting both scopes drive it would mean whichever confirmed last silently wins. How International spend should combine with Domestic for Campaign Creation's channel picker is an open product decision (§11).

The reporting view§ 07

Shown only once a budget exists for the selected year+scope, top to bottom:

  1. Plan Setup — Active status, "View budget detail →".
  2. Budget summary charts — Plan Pacing (committed vs. remaining, over/under against the current day of year), Budget Tracking (Unplanned / Planned / Active / Completed), Channel Media Mix (YTD/QTD/MTD).
  3. Budget detail — one unified view (mbdRenderUnified()) with four components: A. Marketing Loop allocations (five stages, $ and share); B. Channel totals (Direct Mail, Digital, TV, Consumer Print Advertising, …) with C. sub-channels that roll up to them (expand a total to see e.g. Digital = Search, Social, Addressable); and D. Monthly distribution (working, non-working, total by month). Non-working lines follow directly under the working-media table in the same columns, and Total marketing spend (working + non-working) is read-only underneath. For an uploaded budget the sub-channels are its Verilume categories and the Loop stages are derived from the channel-by-stage research (categories with no channel research use the account's stage split, and the view says so) — and this is where the client assigns Loop totals: each stage's $ is an input; editing one rebalances the others to the working total and saves per upload (stageAllocationsJson, POST …/stage-allocations, "Reset to the derived split" to clear); for a saved Media Plan the sub-channels are its channels and the stages are as allocated. Actions: edit categories & labels, download the monthly CSV, and edit/build the media plan — which reveals Steps 1–4 (otherwise tucked away), plus Budget History & Forecast with 2+ saved years.
  4. Active Channels — the account-level channel tiles (§08).
  5. Non-Working Media — agency, analytics, production and similar vendor spend by vendor and month, with an editable client label per row and a CSV vendor upload; feeds the Total Marketing Budget.
  6. Upload history — the audit trail of every upload attempt, accepted or rejected. Always last.

Active Channels gate§ 08

The Active Channels tiles (state.activeChannels, persisted on the account profile) are the single gate on the recommended channel mix: only selected channels receive allocation. Confirming a Domestic upload rewrites the account's set to the channels its mapped, nonzero categories crosswalk to (account_active_channels, plus the always-active owned channels) and returns it, so the tiles update immediately and categories not mapped are unselected automatically. A channel can still be added to a plan by hand regardless of the gate. GET /api/accounts/:id/active-channels?year= reports the year's upload-derived set for Campaign Creation.

Known gaps & open items§ 11 — for product awareness

⚑ Not yet retested in the deployed environment

Rounds 1–7 were verified by syntax checks and (Round 7) a headless-browser run against a stubbed backend. A live pass is still needed: a real file through upload → confirm → Media Plan hand-off, a real International total-only budget, the new Consumer Print Advertising subcategories against a file that names magazines/newspapers, and the monthly CSV export's actual columns.

⚠ International vs. Domestic for Active Channels

Only Domestic confirms drive the account's channel set. Whether and how International spend should combine with it for Campaign Creation is an open product decision; a channel-level International Media Plan would also need a scope on media_plans.

⚠ No manual column-mapping correction any more

Round 4 removed the per-column mapping panel. If the auto-detected column layout is wrong on an unusual multi-block file, the fix is via the category-mapping screen or a cleaner re-upload; the backend still stores everything needed to re-derive the import if a UI is ever wanted again.

⚠ Media Plan .xlsx export depends on a Python generator

xlsx_gen.py won't run on Vercel's Node runtime — every new export this cycle was built as CSV for that reason. The older media-plan/export.xlsx path should be treated as hosting-dependent.

⚠ Audience media-consumption weights are editorial, not licensed research

The generation and wealth-tier channel multipliers added in R8 are directional heuristics (e.g. Boomers over-index on linear TV and newspapers, Gen Z on paid social and CTV). They are disclosed as such in the UI and are meant to be replaced with licensed consumption data when it's on file — the mechanism (per-channel multipliers averaged across the account's selected segments) stays the same.

⚠ Legacy categories still on old data

Display/Programmatic and Magazines/Print remain valid on historical uploads by design; no bulk "remap to the new categories" prompt exists.
