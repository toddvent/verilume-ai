Licensed Integrations

Every third-party vendor the platform is wired to — what it's for, what credential turns it on, and what happens when that credential isn't set. Grounded directly in GET /api/ops/integration-status, the real staff-facing registry already built into the Ops Console — this document explains that registry rather than duplicating a second, driftable copy of it.

Not integrated

Metadata only

Snowflake is a data-capture field, not a connector

Working as designed

Every integration below has an honest non-vendor fallback (template draft, on-screen code, local SQLite, null score) rather than a hard failure when unconfigured.

Known gaps & open items§ 07 — for product awareness

⚠ No automated alerting on vendor-model deprecation

The Gemini retirement this cycle was caught by reading a live 404 response body during unrelated work, not by monitoring. A vendor deprecating a model or rotating an endpoint silently degrades that integration until someone notices.

⚠ No cost tracking per vendor

Integration status reports on/off, not spend. No per-vendor cost dashboard exists — relevant once Licensed Integrations grows past the current 7.

Suggested next steps§ 08

  1. Add monitoring on vendor-model 404s / deprecation notices across all 5 LLM providers.
  2. Decide and scope the Meta integration if it's actually planned — nothing exists to build on top of today.
  3. Build the real Snowflake connector, or remove the metadata-capture fields if it's no longer planned.
  4. Add per-vendor cost visibility once the integration count grows.
