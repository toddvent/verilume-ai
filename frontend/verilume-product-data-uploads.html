Data Uploads & Integrity

How a client's data gets into the platform and how anyone can check that what the dashboards show is what the database holds. Covers the standard customer transaction format, the column mapping a client approves, saves that land completely or not at all, the receipt for every upload, and the data catalog. The customer transaction file is the first and only upload type that has all of it.

The universal transaction format§ 01

One row is one customer line inside a transaction. The Transaction_ID repeats across the rows of one transaction. Revenue on a row is that row's own revenue, never the order total repeated, so the sum of all rows is total revenue. A retail basket is one row per item; a cruise booking is one row per guest.

Order Size is the new base field

Trip Days is stored per customer row (account_guest_bookings.tripDays) and the account labels it (Trip Days, Nights, Units). On the 24 to 26 file it totals 429,940 customer-days against $338.3M gross, about $787 a day. Average daily revenue and marketing CAC per day are built on that total, not on bookings.

Column mapping and approval§ 02

Clients keep their own column labels. The upload reads the file, proposes a match for each standard field, and gives the result back to the client to approve.

1

Read the file

The header row is found automatically (title rows above it are skipped). Up to 300 values per column are sampled.

2

Propose by rules

Each column is scored against each field: the header words (exact match, contained phrase, loose match) weighted 70%, and what the values look like (dates, short codes, whole numbers, ages, amounts) weighted 30%. A header that contradicts its values is penalised. When two columns could be the same field the confidence is capped and the other column is named.

3

AI second opinion for what is left

Fields that are unmatched or below 55% confidence are sent, with the headers and a few sample values, to Claude. It may only choose among the headers sent, and its answer is capped at "Please confirm". It never overrides a confident rules match. If the key is missing or the call fails, the screen simply has no suggestion.

POST /api/accounts/:id/guest-bookings/map-assist
4

The client reviews

One table: our field, the client's column (changeable), a confidence badge (High, Please confirm, Low, Saved mapping, You chose), the reason, and example values. Required fields that are still unmatched block approval; rows needing confirmation require a tick that they were checked. Unused columns are listed so nothing disappears silently.

5

Which statuses count as a sale

Every status value in the file is listed with its row count. The client unticks canceled or voided ones. The choice is written to the account's transaction settings before the save so the monthly totals use it.

POST /api/accounts/:id/transaction-settings
6

Approve and remember

The approved mapping, the order-size label and the list of ignored columns are saved per account with who approved and when. The next file with the same columns skips the review screen and shows a one-line note with a link to review. A renamed or new column brings the screen back.

GET / PUT /api/accounts/:id/upload-mapping?kind=guest_bookings

Confidence tiers: High is 80% and above, Please confirm is 55% to 80%, Low is below 55%. Tested on the 15-column file from the first client (all High) and on a retail-style file with unfamiliar headers (required fields found, weaker matches flagged).

All-or-nothing saves and receipts§ 03

The browser sends the file in chunks of 500 rows, each with a two-minute wait. Every chunk goes to account_guest_bookings_staging under one upload ID. Nothing in the live table changes until the final chunk, when one transaction deletes the months the file covers, copies the staged rows in and clears the stage. A browser that gives up halfway leaves the live data untouched, and the client is told nothing changed.

The upload receipt

The final call also carries what the browser counted in the file. The server counts what the live table now holds for the same months and stores both in upload_receipts: customer rows, unique transactions, gross revenue and, new, order-size units, in total and by month. The receipt says whether they match and, if not, exactly which counts differ. It is shown on the upload screen and in the Ops Console.

Rows that are skipped

A row with no transaction ID or no readable transaction date is skipped and counted on the read-out, so totals rows, blank rows and the "applied filters" footer in an export never reach the database. On the 24 to 26 file three rows were skipped this way and the receipt matched exactly.

Source stamps and integrity checks§ 04

  • Source stamps. The Strategy and Growth & Performance analytics responses carry a provenance block (what each number was computed from, and when that upload last landed). The cards show it as a small source line.
  • Data Integrity panel. A staff-only panel in the Ops Console lists, for an account, each table's row counts and the latest upload receipts.
    GET /api/ops/accounts/:id/data-integrity (X-Admin-Token) and GET /api/accounts/:id/data-integrity (session).
  • Report Cards panel. A staff-only list of every report card (date added, Verilume default or client, name, formula, source tables). It is hand-maintained.
    GET /api/ops/report-cards

The data catalog§ 05

DATA_CATALOG in server.js has one entry per data set: owner dashboard, grain, keywords, who uses it and status. Train the Brain's "Data consumed" view reads it. catalogCoverage() lists any table with an account ID that has neither an entry nor an exemption, and backend/check-data-catalog.js exits non-zero for one; run it before deploying.

This cycle: the guest booking entry is now "Customer transaction file" (one row per customer line, with order-size keywords), and Upload receipts and Upload column mappings were added as data sets. The upload staging table is exempt because it is transient.

Known gaps & open items§ 07 — for product awareness

Transaction path tested on SQLite only

The all-or-nothing commit runs as one transaction through db.batch(). It has not yet run against Postgres in production. The first full upload is the real test; the receipt will say whether it matched.

Receipts and mapping cover the customer transaction file only

Lead counts, website users, digital performance and budget uploads still save without a receipt and without the mapping screen.

AI second opinion not exercised with the live key

The endpoint returns an empty suggestion list when the Anthropic key is missing or the call fails, so the screen works without it. It was not run against the live key.

Product code and customer ID are not stored

Primary and Secondary Event Code stay unused. Customer_ID does not exist in the current file. New vs repeat customer analysis waits on it.

Fractional Trip Days in the source

256 of 44,378 rows carry values such as 9.984 and 13.056. They are stored as given; the cause is in the export.

Status codes need the client's meaning

R, V, W, O and I all start ticked as "counts as a sale". Nobody has confirmed which mean canceled.

Per-day KPIs are not on the cards

Average daily revenue and marketing CAC per day are defined (see Next steps) but not built. They need the order-size column populated for the months shown.

Saved mapping matches on header text

A renamed column re-opens the review screen. That is intended, but a client who changes export settings will see the screen again.

Suggested next steps§ 09

  1. Run the full 24 to 26 upload on the live site and read the receipt and the Data Integrity panel. This is the first test of the Postgres commit path.
  2. Build average daily revenue (gross revenue divided by customer-days) and marketing CAC per day (marketing cost divided by customer-days of marketing-attributable transactions, with the all-transactions version beside it) on the Growth & Performance cards.
  3. Add the five text and five number custom fields, stored as JSON per row and named by the client, filterable but outside the forecast unless mapped.
  4. Extend receipts and the mapping screen to lead counts, website users, digital performance and budget uploads.
  5. Add Product_Code and Customer_ID, and a small set of industry presets that rename labels and choose which size metrics to show.
