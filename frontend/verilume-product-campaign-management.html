Campaign Management

The campaign record that every other Marketing & Analysis surface reads from: Performance Marketing's audience targeting, Channel Plan's approved channel mix and spend, Creative's Step 0 recap, and the AI copy engine's objective-driven templates all key off one campaigns row (backend/server.js, frontend/portal.html's Campaign Detail page and cmp* functions). This document is new as of the 2026-09-22 data-source-of-truth consolidation — it did not exist before that cycle — and covers the campaign data model as verified against the live code and Supabase on that date.

Owner Todd Brown System verilume.ai — backend/server.js, frontend/portal.html (Campaign Detail page, cmp* functions) Verified against working tree + direct Supabase queries, 2026-09-22 (dead-field consolidation) Status Built and live; this is the first Product doc written for this area

Headline findingsthis cycle

Root cause found

Three columns duplicated real data, and were empty on every real campaign

campaigns.audienceTargets, .channels, and .objective (narrative use) were each shadowed by a different, genuinely-populated field. Confirmed by direct SQL against all 4 real campaigns in the account: every one of them was empty on all three dead columns.

Bug found

A "smart default" could look saved without ever being saved

A client-side auto-fill feature silently pre-filled form fields from account history without calling any save function, so a field could read as filled-in in the browser while Supabase still had NULL.

Bug found

The ad-copy objective template lookup was silently failing on every real campaign

Every Marketing Function Project generator (Social Batch, Email Sequence, Landing Page, Press Release/Email/Landing) resolved its objective-driven copy line by reading the dead objective column — always empty, so it always fell back to a generic line. Fixed by deriving the category from stage instead.

Resolved

One source of truth, per field, everywhere

Every read and write site for these three fields — frontend and backend — was migrated onto the real underlying field. See Data model reference for the final mapping.

Campaign lifecycle overview§ 01

A campaign moves through Media Mix recommendation → Performance Marketing validation → Channel Plan approval → Creative production, each stage reading the previous stage's real, persisted output rather than a copy of it.

01

Recommended Mix

An illustrative channel & audience mix and spend split is generated from the campaign's stage and budget — a starting point, fully human-editable, not itself persisted as the source of truth for anything downstream.

02

Performance Marketing

Validates the buy/allocation, and sets the audience target this campaign is actually going after — written to campaigns.segment. Skipped entirely for Ad Hoc projects.

03

Channel Plan approval

Per-channel budget/impressions rows are approved into real channel_planning_details records (one row per channel, status: 'approved'); the campaign's mediaMixJson also reflects the approved per-channel dollar amounts.

04

Creative Asset Selection

Opens once Channel Plan is approved. Creative's Step 0 recap reads the campaign's real audience (segment), channels (channel_planning_details/mediaMixJson), and objective (activityNotesJson.objectivesGoalSummary) — read-only from here on.

Performance Marketing & audience (segment)§ 02

The Performance Marketing card ("Validate the buy & set audience targets") is the one place a human sets this campaign's audience. As of the 2026-09-22 consolidation its Validate & Save action writes into campaigns.segment — the field every other reader in the app (Creative, Marketing Ops, the AI Brain contribution ledger) already reads for audience.

Fixed this cycle — the field used to write nowhere real

Before this cycle, Validate & Save wrote to campaigns.audienceTargets, a column nothing downstream ever read. Supabase confirmed it was empty on all 4 real campaigns in the account even though Performance Marketing had genuinely validated buys. Todd's explicit direction was to repoint the save to the real field rather than make the card read-only, so this workflow is now the live audience of record.

A separate "smart default" pre-fills this same textarea from the account's recent-campaign history when the form first loads. Before this cycle that fill never triggered a save — a field could look complete in the browser with nothing in Supabase. It now calls the save action automatically the moment it silently fills the field.

Channel Plan & channels§ 03

The Channel Plan's Approve action (cmpApproveChannelPlan()) does two things: it writes one real channel_planning_details row per planned channel (budget, impressions, status approved), and it keeps campaign.channels/channelGroups set in the browser's in-memory campaign object for the rest of that session's UI. As of this cycle it no longer writes channels/channelGroups back to Supabase — Supabase confirmed nothing reads that column back once a page reloads, so the write was pure duplication of the channel_planning_details rows written in the same action.

Every reader in the app that used to read campaign.channels directly — leaderboards, CSV exports, search/relevance scoring, the Channel Plan picker's own initial state, Creative's recap — now goes through one shared helper, cmpCreativeChannelsText(c): real column first (for any pre-existing local-only data), falling back to the approved channels with budget > 0 in mediaMix.channels.

Creative handoff (Step 0 recap)§ 04

Creative's Step 0 recap is the read-only summary Omni-Channel Creative sees before starting production — Audiences, Approved Channels, and Objective. This is what originally surfaced the whole consolidation: the recap showed blank Audiences/Approved Channels on a genuinely complete campaign, because it was reading the dead audienceTargets/channels columns instead of segment and the real channel-planning data.

Three shared helpers now back this recap and every other audience/channel/objective reader in the frontend:

HelperReal source (checked first)Dead-column fallback (pre-existing local-only data only)
cmpCreativeAudienceText(c)segmentaudienceTargets
cmpCreativeChannelsText(c)mediaMix.channels where amount > 0channels
cmpCreativeObjectiveText(c)activityNotes.objectivesGoalSummaryobjective

Objective: narrative goal vs. copy-template category§ 05

campaign.objective is not a simple duplicate the way audienceTargets/channels were — it was overloaded across two genuinely different concepts sharing one column, and each needed its own fix.

Narrative business goal

Free text describing what this campaign is trying to achieve, used in AI-prompt context (content/image relevance scoring, the campaign-intake digest, CMO team messages). Now sourced from activityNotesJson.objectivesGoalSummary via cmpCreativeObjectiveText() (frontend) and campaignObjectiveText() (backend).

Canonical funnel-stage category

One of a fixed 5-value set (Brand Awareness, Consideration, Purchase / Conversion, Brand Loyalty, Brand Advocacy) that keys CAMPAIGN_OBJECTIVE_COPY, the pre-written ad-copy template table every Marketing Function Project generator uses. For the live creation form this was already correctly derived from selectedStage via cmpCurrentObjective(). For a saved campaign it was still reading the dead objective column directly — fixed this cycle with cmpCampaignObjectiveCategory(campaign), deriving from campaign.stage the same way.

StageObjective category
AwarenessBrand Awareness
ConsiderationConsideration
PurchasePurchase / Conversion
LoyaltyBrand Loyalty
AdvocacyBrand Advocacy

One deliberately untouched pattern: the c.name || c.objective "Untitled Campaign" display-name fallback (~28 sites in portal.html, ~4 in server.js) is a separate, intentional convention, not part of this fix.

Known gaps & open items§ 07 — for product awareness

  • A separate set of unrelated lowercase-duplicate columns (campaigntype, rolestyle, mandatoryphrase, and others) exist from an old migration and hold zero rows anywhere in the account. Flagged, out of scope — nothing reads them, so they cause no bugs, but they're dead weight in the schema.
  • This doc covers the campaign data model as it stood after the 2026-09-22 consolidation. Campaign Creation intake, the CMO Dashboard, and portal-wide analytics that also touch campaigns are not yet covered here — see the (not yet documented) CMO Dashboard & Portal Navigation card on the home page.

Suggested next steps§ 09

  1. Document Campaign Creation intake — how stage/segment/budget get set in the first place, and how the Recommended Mix illustrative split is generated. This doc starts at Performance Marketing; intake itself isn't covered yet.
  2. Consider retiring the dead columns outright (audienceTargets, channels, channelGroups) now that nothing writes to them — currently they're kept only as a fallback for old local-only data, which will age out on its own.
  3. Clean up the unrelated dead lowercase-duplicate columns flagged in Known gaps, separately from this cycle's work.
  4. Document the CMO Dashboard & Portal Navigation card, still listed as not-yet-documented on the home page, since it's the other major consumer of campaign data in this Product group.
