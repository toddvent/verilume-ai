Reference Data Staff only

The Population Index and DMA roll-up every account's Match Market Builder results depend on need two shared reference files no client supplies: population by zip (U.S. Census, free) and a zip→DMA crosswalk (DMA boundaries are Nielsen's; the free crosswalk is a public approximation, labelled that way wherever a DMA appears — a licensed Nielsen file can be loaded below and replaces it). Zip centroids (for store trade areas) are the same kind of one-time, shared load. None of this is account-scoped — one load here serves every account.

Click "Check status" to load current counts.

2020 Census ZCTA population + public zip→DMA crosswalk, fetched server-side through this console's own session and saved to the backend in batches. Needs a Census API key configured as the CENSUS_API_KEY environment variable on the backend — if that's missing, this will say so directly.

Demographics: 2022 ACS 5-Year age (5 generations: Gen Z, Millennials, Gen X, Boomers, Silent Gen — the same ones Company Profile's generation picker can actually back with real Census data) and real per-bracket household income counts, by zip — feeds the Match Market Builder's per-store trade-area Audience/Wealth Fit scoring and the Test/Control demographic matching dimension. Same Census API key requirement as above. Pulled per state (50 states + DC + Puerto Rico) and merged — a prior version pulled the whole country in one flat query, which Census's ZCTA geography doesn't support reliably and silently returned only 2.7% of zips nationally. Use "Test these states" with a couple of sample states first to confirm real per-zip coverage before running the full national reload, which takes noticeably longer (dozens of Census API calls).

IRS top-bracket income: real per-zip average income for households earning $200,000+ (IRS Statistics of Income, ZIP Code Data — irs.gov, free, no API key, one national file). Census's own income table can't tell a $225,000-average area apart from a $2,000,000-average one — both land in the same open-ended top bracket — so this fills in the one number Census can't provide, letting genuinely wealthy areas score as such. Independent of the Census demographics load above; run both for the most accurate Wealth Index.

Setup instructions — what to do once a client requests a pathway

A submitted request only sets analyticsStatus = 'requested' — nothing below happens automatically. Work the steps for the client's chosen pathway, then set Status to Connected above once done.

GA4 — client adds Verilume's service-account email as Viewer in their GA4 Property Access Management, and provides their Account ID + Property ID. Fastest pathway — same-day, no approval step on either side. The real connector already exists (GET /api/accounts/:id/ga4-report); it activates automatically once production has a real GA4_SERVICE_ACCOUNT_KEY_JSON credential — check with engineering before promising a client live data.

Snowflake — client's own data team provisions a read-only Secure Data Share (never full warehouse access) and provides the account identifier, Share name, and a data-team contact (still what this form above captures). 2026-09-13 update: the pull connector itself is now real code (syncSnowflakeAccount() in server.js, key-pair JWT auth against Snowflake's SQL API, nightly cron at GET /api/cron/sync-snowflake) — it lands call/lead/booking records into warehouse_calls/warehouse_leads/warehouse_bookings. It stays dormant until two separate things exist: (1) Verilume.AI's own Snowflake account + SNOWFLAKE_* env vars in production, and (2) per-account provisioning — which database/schema/table the client's mounted share landed as, set via the admin-only POST /api/accounts/:id/snowflake-connector-config (not a form on this page; there's no client-facing UI for Verilume's own internal database naming). So "Connected" above still means "request fully documented" until an engineer does that provisioning step and a real sync succeeds — check with engineering before promising a client live data.

Meta — client adds Verilume's Business Manager System User with ads_read permission on the ad account(s) to report on. Slowest pathway — Meta's App Review realistically runs 1-2+ weeks, and that's Verilume's own one-time step, separate from any one client. No connector code exists yet.

Google Ads / SA360 — client grants Verilume's OAuth app read access to their Google Ads account or MCC. Gate is Verilume's own one-time Developer Token approval (Google's process, days-weeks), not the per-client grant. No connector code exists yet.

Fallback (Google Sheets / manual notes) — client shares a designated Sheet, kept current with their own campaign data in an agreed format. Real risk is staleness, not setup friction. No reader exists yet — this pathway stays notes-only until one is built.
