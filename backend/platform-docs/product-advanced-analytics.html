Advanced Analytics: MMM Light and market testing

Current-state reference for the model, its schedule and credits, the qualification check, and the handoff from a model's test candidates into market design and the Truth Lab.

Updated 2026-11-22 · Build 2026-11-22-r97 · Status: built and tested against mocked data; not yet verified on the production site. Training guide (PDF) · Training guide (web) · All Product docs

01 What it is

MMM Light fits a weekly regression to an account's own daily records and campaign plans, with carry-over (geometric adstock), diminishing returns (Hill saturation), trend and seasonality, a nonnegative ridge, a 13-week holdout and bootstrap ranges. It recommends a reallocation within guard rails and lists channels worth testing. The model code is server-only (mmm-model.js).

Positioning. Reported numbers come straight from the data; modeled numbers show a range and confidence. MMM Light is not a Bayesian model, is not calibrated to test results, does not model markets separately and reads weeks, not days. Where a deeper model fits, Verilume brokers one from Measurement Coverage. Portal and home-page copy say so.

04 Handoff to testing

  1. The run stores testPlan: channel, why, extra weekly spend, expected lift [low, mid, high] as % of mean weekly outcome.
  2. Plan this test stores a candidate in the portal and opens Visualize markets (step marketOptimization). The earlier link on the Test next card pointed at the Data Visualizer; fixed in r97.
  3. The page requests geo-approach?liftPct=<mid>. The server returns the cached approach plus forLift: weeks, verdict (readable up to 13 weeks, longer up to 26, too_small beyond) and text.
  4. Save writes a draft Truth Lab test linked to the run. Markets and dates are added in the Truth Lab. Confirming a result remains a person's decision.

05 Known gaps

  • Nothing here is verified on the production site; route tests were run against a mocked portal and a synthetic fixture, and the schedule timer has not run on a live server.
  • Test results do not calibrate the model. Accept-and-log decision, partner-supplied MMM results, impressions as exposure and daily actual spend load are not built.
  • The Truth Lab does not yet show the linked MMM run on a test; the link is stored in the test's details.
  • weeks needed uses the pooled markets only; per-pair sizing is on the existing approach card.
  • The refresh timer is single-process; a multi-instance deploy would need a lock.
  • No UI for a per-account price override; no notice when a refresh pauses.
  • AI Media Plan recommendations are not yet constrained to budget channels (current gate is Active Channels).

06 Qualifying a real account

Use the qualification check on the MMM Light page, then send the copied request to the client. For a client that supplies calls and leads through a data warehouse share, the real column names for call attribution (UTM source, medium, campaign, referring site) are needed before those fields can be mapped; until then they sit in the raw payload.
